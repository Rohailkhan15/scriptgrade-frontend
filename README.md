# Frontend Masterpiece

I have provided a detailed frontend specification below. Treat this document as the primary source of truth for this project.

First, carefully read and analyze the complete specification before making implementation decisions. Understand the application structure, pages, navigation, components, design system, colors, typography, spacing, responsiveness, interactions, and all other requirements described in it.

Then implement the frontend according to the specification.

Important instructions:

Follow the specification as closely as possible. Do not arbitrarily change the defined design, structure, pages, colors, typography, or user experience.

If the specification contains ambiguity or conflicting requirements, choose the most professional and consistent solution while preserving the intended design system.

Focus primarily on creating a high-quality frontend. Use mock/static data where backend functionality or real APIs are not yet implemented.

Do not spend time implementing unnecessary backend features, databases, authentication, APIs, or integrations unless they are explicitly required in the specification.

Build all pages, layouts, navigation, components, and UI states described in the specification.

Create reusable components wherever appropriate. Avoid duplicating UI code.

Establish and consistently follow the design system defined in the specification across the entire application.

Pay close attention to visual hierarchy, spacing, alignment, typography, component consistency, and overall polish.

Ensure the interface looks professional and production-ready rather than like a generic AI-generated website.

Make the design fully responsive for desktop, tablet, and mobile.

Ensure there is no unnecessary horizontal scrolling or broken layout at different screen sizes.

Include appropriate hover, focus, active, disabled, loading, empty, and error states where relevant to the frontend.

Use accessible semantic structure and maintain sufficient color contrast.

Keep the UI clean and intentional. Do not add unnecessary gradients, excessive animations, decorative elements, oversized text, or visual effects unless explicitly specified.

Use consistent icons and component patterns throughout the application.

Preserve a clear separation between reusable UI components and page-specific components.

Implementation process:

Read and understand the entire frontend specification.

Identify the application's design system, page structure, navigation, reusable components, and responsive requirements.

Build the shared application shell and global design system first.

Implement the pages and reusable components systematically.

Use mock data where required.

Ensure consistency across all pages.

Review the completed frontend for visual inconsistencies, responsiveness issues, duplicated components, alignment problems, and poor UX.

Fix meaningful issues while preserving the requirements and design direction from the specification.

Do not ask unnecessary questions or make assumptions that contradict the specification. If something important is genuinely unclear, make the most reasonable professional implementation decision consistent with the rest of the document.
